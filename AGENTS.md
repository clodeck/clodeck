# AGENTS.md

## Language

Respond to the user in **Finglish** = Persian written in Latin letters, never in Persian script — even when the user's own message is in Persian script. Keep technical terms in English.

## Project

This repo hosts a **wayfinder** effort. Destination: a *spec* plus a *visual prototype* for a **web UI that rides on the Claude Agent SDK** — remote browser access to Claude Code across multiple project directories, running on a dedicated server, visually modeled on `claudecodeui` (github.com/siteboon/claudecodeui).

- **Issue tracker:** local markdown under `.scratch/<effort>/` — the local tracker is still the default now that the repo has a GitHub remote (`clodeck/clodeck`). Map = `.scratch/<effort>/map.md`; tickets = `.scratch/<effort>/issues/NN-<slug>.md`.
- **Domain docs:** `GLOSSARY.md` / `docs/adr/` created lazily by the domain-modeling skill.

## Git workflow

**Never commit on `main`.** Every change — code, docs, tickets, handoff — goes on its own branch, and lands on `main` only by an explicit merge.

1. **Branch first.** `git switch -c <effort>/<ticket>-<slug>` off `main` before the first commit (e.g. `clodeck/31-terminal-accumulates-on-switch`). No ticket? Use the effort name plus a short slug, and a `docs/` prefix for a docs-only change.
2. **Commit on the branch**, one commit per coherent change, in the repo's own style (lowercase scope prefix, a sentence saying what and why). The pre-commit hook runs the tracker check, `npm run typecheck` and `npm test` — a red tree is never committed; `--no-verify` only if the user asks for it. CI repeats the same list on a push to `main` and on every PR to `master`.
3. **Stop at the merge, and never publish.** Do not merge into `main`, do not push, and do not open a PR unless the user asks. When they ask for the local merge: `git switch main && git merge --no-ff <branch>`, then delete the branch. **`master` is production**: it moves only by a pull request from `main` merged as a merge commit, which a person opens with `npm run pr` (`git push origin main` + `gh pr create --base master --head main`). Never merge into `master`, never push to it, and never force-push anything.

A docs-only or handoff-only change is **not** an exception.

## Standing decisions (this effort)

- Destination = spec + prototype (not a full build yet).
- Single user; a dedicated server hosts both the UI and all project folders.
- Build from scratch; `claudecodeui` is the visual/feature reference only.
- Branches and delivery (**ticket 93**, 2026-10-22): `main` is integration and the only branch agents merge into (locally, on request); `master` is production and moves only by a PR from `main` merged as a merge commit — never a direct push, never a force-push, never an agent. CI (`.github/workflows/ci.yml`) runs the composite verify list — tracker check, typecheck, test, build — on every push to `main` and every PR to `master`; `deploy.yml` runs the same list on `master` and then deploys over a forced-command SSH key (`scripts/clodeck-deploy.sh`), rolling the server back to the previous commit if build, restart or `/healthz` fails. A server rollback does not rewrite GitHub's `master`; undoing a bad publish there is a manual revert PR.
- Primary interaction: chat over the Agent SDK, plus a per-project shell terminal and file drawer.
- Each project = one directory = one Agent SDK session + terminal + a file drawer (scoped read **and** write); a project switcher on top. A project is still an immediate child directory of the projects root — the root stays the allowlist, `id` stays `base64url` of the canonical path, and there is no registry or metadata — but adding one is **no longer a filesystem-only action**: the UI can also create one with `POST /api/projects` (decision 2026-10-13, `.scratch/clodeck/issues/46-project-creation-decision.md`; built by ticket 47). The filesystem stays the mechanism, it stops being the only door. Removing one is the same door in reverse: **a real delete** — `DELETE /api/projects/:id` removes the directory recursively, never a trash and never a registry, refusing while a run is live or a terminal is attached, behind a typed-name confirmation (decision 2026-10-21, `.scratch/clodeck/issues/87-delete-project-decision.md`). The SDK transcripts under `~/.claude/projects` are deliberately left in place.
- Layout (**web-claude-ui decision 03**, Variant A — "chat first, tools on demand"; not the `D3` in the MVP bullet below): a narrow icon rail ▸ project sidebar ▸ chat stage. The sidebar lists projects only; sessions stay behind the chat header's History button. The terminal **and** the file drawer live in **one summonable bottom drawer** opened from the rail and shut on first load — they are never a permanent column beside the chat.
- File access is scoped to the project root: every path is re-validated by `realpath` containment. Writes never follow a symlink in the target's final segment, never overwrite on create/upload/move (the save route is the one deliberate overwrite, and it refuses a non-file target), and can never touch the project root.
- Stack: Node/TypeScript backend (Agent SDK TypeScript) + React/Vite/Tailwind + xterm.js. (.NET considered and rejected: the Agent SDK ships TypeScript/Python only — no .NET binding — so a .NET backend would shell out to a sidecar anyway.)
- Auth: single-account login (like claudecodeui) over HTTPS — no Tailscale, no raw HTTP basic-auth. The session cookie's `Secure` flag follows the **declared public origin** (`CLODECK_PUBLIC_URL`), so a bare `http://` origin is a supported **direct route** — cleartext, and warned about at startup and on the login screen — while an undeclared origin keeps the cookie `Secure` exactly as before (`docs/adr/0001-session-cookie-follows-public-origin.md`).
- Provider profiles (**decision 2026-10-15**, `.scratch/clodeck/issues/66-provider-profiles-decision.md`; built by tickets 67–70): a **session**, not a project, chooses the provider it runs on — a cheap model for grunt work and a strong one for design in the same project, switched between. A profile is a *patch* over the server's environment (`CLODECK_PROVIDER_<NAME>_*`: any subset of endpoint, credential and model, the rest inherited) and the reserved default profile is the server's own environment. **Endpoint and credential travel together; the model travels free** (`docs/adr/0002-provider-credentials-travel-with-their-endpoint.md`): a project whose `.claude/settings.json` declares either one keeps both, and a session's choice degrades to the model — because that file already overrides the server's `ANTHROPIC_*` **per key**, so a single key in it could otherwise send a credential to a host it was never issued for. The effective provider is always shown, and clodeck still persists nothing. This narrows ticket 07's *"the server never handles the API key"* to **never stores, never persists, and never invents one**.
- Permission modes (**decision 2026-10-21**, `.scratch/clodeck/issues/81-permission-modes-decision.md`; built by tickets 82–84): a **session**, not a project, chooses the mode it runs under — **Ask** (`default`), **Accept edits** (`acceptEdits`), **Plan** (`plan`) or **Bypass** (`bypassPermissions`), defaulting to `CLODECK_PERMISSION_MODE` with a per-session override in the composer line. The four labels are clodeck's **contract**, not the SDK's constants (`docs/adr/0003-permission-modes-are-a-contract-not-an-sdk-passthrough.md`): in Ask and Accept edits **every Bash call asks** — read-only commands and filesystem commands included — and in Plan edits and Bash are **denied without a prompt**; `auto` and `dontAsk` are refused at the wire. A project's `.claude/settings.json` can **tighten, never loosen**: its deny/ask rules always apply, its allow rules are neutralised for these four modes. Bypass is gated by `allowDangerouslySkipPermissions`, `CLODECK_ALLOW_BYPASS` and a project's `disableBypassPermissionsMode`; the mode lives in the run and is never written to disk.
- MVP scope: streaming chat + the session's permission mode + session history/resume + project switcher (with **creating a project from the sidebar**, `POST /api/projects`, and **deleting one**, `DELETE /api/projects/:id`) + file drawer (scoped read + write: inline tree expansion + new file, new folder, rename, delete, upload, drag-move of a file onto a folder, download of a file's real bytes, content editing via an editable toggle + save, markdown preview with a `Preview ⇄ Source` toggle, `size · modified` on file rows, a tree ⇄ flat-list toggle, and a line-number gutter + rough syntax colouring in the code view) + shell terminal. Download, markdown preview, file-row metadata, the tree ⇄ list toggle and drag-move were promoted from out-of-MVP by decision **D3** (in `.scratch/clodeck/prototype-parity.md`, 2026-10-12); the code view's gutter and colouring are the one **P2** item that decision selected; creating a project from the UI was brought in by the 2026-10-13 decision on ticket 46 (built by ticket 47); deleting a project from the UI was brought in by the 2026-10-21 decision on ticket 87 (real delete, typed-name confirmation, refused while live); **per-session provider profiles** were brought in by the 2026-10-15 decision on ticket 66 (built by tickets 67–70), under the credential rule the provider bullet above states; **the session's permission mode** was brought in by the 2026-10-21 decision on ticket 81 (built by tickets 82–85), under the four-mode contract the permission bullet above states; the composer's **`/` command menu** was brought in by ticket 75 (2026-10-17, `.scratch/clodeck/issues/75-slash-command-menu.md`) — `/` lists the **session's own** commands, filtered as you type, derived from `.claude/` in the project and in every directory above it up to the projects root before the first send and from the SDK's own list (built-ins included) after it, with the SDK's terminal-bound commands hidden, and never clodeck's own buttons. Out of MVP: git explorer, plugins, browser-use.
